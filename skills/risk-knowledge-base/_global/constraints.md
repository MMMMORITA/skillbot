# 全局约束与可信规则

> 本文件是知识库的元层：不属于任何业务类目，承载「这个 KB 什么时候可信、作答要遵守什么纪律」的规则。
> **检索与作答的第一步必须先读本文件。**

## 问题类型判断

把用户问题先归为一类，决定检索重点：

- **口径查询**（某指标怎么算、口径是什么）→ 直查指标口径文档（`01_风控总览/PIPO支付风控核心指标口径OnePager.md`）与相关类目原文。
- **计划 / 方案生成**（出一版风控策略、规则集）→ 先定位涉及的指标口径与风险类型文档，再组织方案，每处指标/规则点名来源。
- **归因分析**（拦截率/误杀率为何变化、某业务线异常）→ 先确认口径，再查对应业务线（`02_业务场景/`）与风险类型（`03_风险类型/`）文档。
- **复盘 / 背景**（历史决策、案例）→ 查对应类目原文作为事实底座。

## 可信规则（防「假权威」）

- **KB 是参考，不是答案**：命中内容须经你自身判断后再用；与问题明显不符时以推理为准，并显式说明「KB 内容与本问题不符，未采用」。
- **口径以带 `source_url` 的原文为唯一准绳**：无来源的数字、阈值、口径不得直接引用；多个来源冲突时列出并说明取舍。
- **未覆盖如实声明**：KB 未覆盖的问题，明确说「知识库未覆盖」，回退到常规推理，**禁止用相邻文档强行套用**。

## 输出纪律

每次基于 KB 作答，输出须包含四要素：

1. **结论**：先给直接答案。
2. **证据**：引用到具体 MD 文件与 `source_url`（格式见下）。
3. **下一步**：需要用户确认或补充的信息、后续动作。
4. **口径说明**：本次采用的指标定义 / 时间窗 / 过滤条件 / 去重口径；若使用了默认值，标注「默认值可能与你的预期不符」。

引用格式统一为：`来源：<类目>/<文件名>.md（source_url: <链接>）`，例如
`来源：03_风险类型/TTS-ROW交易黑标V4.md（source_url: https://.../docx/NdvHda7wdoYg2pxIP3imRObVyKd）`。

引用只保留「类目/文件名.md」与 `source_url` 两项，务必从简：

- **禁止输出内部元数据**：`token` / `source_token` / `doc_id` / `source_type` / `last_synced` 等字段对用户无意义，且 `token` 已包含在 `source_url` 末段，不得重复列出。
- **同一来源只引用一次**：正文用文档简称，链接集中在末尾统一列出，不在正文重复贴 `source_url`。
- **多篇来源**：逐行列出，每行一条，仍遵守上述两条。
