## 适用场景
提供一版更适合拦截模型训练或评估的黑白标签，按需使用。在原黑白标签方案基础上做黑种子提纯、关联逻辑简化与打标规则调整，用于引导拦截策略聚焦黑标样本以及 Swap（拦截释放）分析。

## 核心概念
- 黑种子优化：剔除后黑种子为非FF的 fraud CB 和人审黑名单；剔除生态同人黑标；按新定案件分类剔除 FF。
- 白种子：强可信 和 oncall+appeal 成功。
- 关联逻辑：只看1度关联，强介质保持 user、pi、device 三个不变。
- 打标5级：EVIL/ANGEL/BAD/GOOD/GREY，基于 black_vote 与 white_vote 比较。

## 关键指标口径
- frd_amt_rat：EVIL 标签中成功金额里实际报回 FraudCB 的比例（约17%）。
- amt_to_frd：EVIL 标签覆盖总金额中实际转化为 FraudCB 的比例（约6%）；Swap 释放分析建议以 10% amt_to_frd 作偏严估算。
- 整体分布：evil+bad 约0.9%（20260101-20260531 分区），evil 中大部分为 fraud。
- 已拦截交易中：evil 占6.5%、bad 占1.6%。

## 规则 / 策略要点
- 打标规则：仅关联黑种子不关联白种子=EVIL；仅关联白种子不关联黑种子=ANGEL；黑种子>白种子=BAD；白种子>黑种子=GOOD；否则 GREY（SQL 基于 black_vote/white_vote）。
- lowrisk 分布：Evil 案件75%在非lowrisk，Evil 非FF案件90%在非lowrisk；Good/Angel 的 fraud 多落在 lowrisk。
- 落表：pipo_risk_strategy.risk_payin_webapp_txn_tagging_1hop_propagation，字段 tag0_vote，回溯 20260531 分区含过去180天有损渠道交易。

<title>黑白标优化</title>

一版更适合拦截模型训练或评估的标签。按需使用。

# 优化点

1. 黑种子优化：\*剔除后黑种子为非FF的fraud cb和人审黑名单。白种子为强可信和oncall+appeal成功。

   1. 剔除生态同人黑标
   2. 按照新定的案件分类，剔除FF
2. 关联逻辑优化：

   1. 只看1度关联，关联介质保持 user, pi, device三个强介质不变。
3. 打标优化：

   1. 如果一笔交易只和黑种子关联，不和白种子关联，则为EVIL。即当笔交易所使用的强介质上只有非FF案件和人审黑名单交易，且没有任何可信交易和人审通过白交易（下面各类逻辑以此类推）。
   2. 如果一笔交易只和白种子关联，不和黑种子关联，则为ANGEL
   3. 如果一笔交易关联的黑种子>白种子，则为BAD
   4. 如果一笔交易关联的白种子>黑种子，则为GOOD

```SQL
case 
    when black_vote > 0 and white_vote = 0 then 'EVIL'
    when white_vote > 0 and black_vote = 0 then 'ANGEL'
    when black_vote > white_vote then 'BAD'
    when white_vote > black_vote then 'GOOD'
    else 'GREY'
end as tag0_vote
```

- 整体分布: evil + bad 大约0.9%, evil中大部分是fraud。由于剔除了FF，ANGEL/GOOD/GREY中也会含有fraud。但如果看non_ff_fraud，ANGEL/GOOD中只有少量fraud。
