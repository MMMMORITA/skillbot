# SCHEMA.md — 风控知识库约定层（“宪法”）

> 新增或更新任何**知识文档 MD** 必须遵守本约定。目的：保证 agent 路由与指标命中的一致性，避免同义词发散。
> 例外：`_global/` 下的元层文件（如 `constraints.md`）不承载业务知识、不进 `manifest.json`、不遵循下述 frontmatter/分节约定，仅承载全局规则。

## 一、10 类目定义与边界

| 目录 | 类目 | 收录范围 |
|---|---|---|
| `01_风控总览` | 风控总览 | 全局性概念、账号体系、核心指标口径、CheckPoint、3DS 等基础设施类 |
| `02_业务场景` | 业务场景 | 按业务线（电商 / TikTok Live / Local Service 等）的风控介绍 |
| `03_风险类型` | 风险类型 | 交易黑标、黑白标签定义、False Positive 分析等风险刻画 |
| `04_规则与策略` | 规则与策略 | 规则调优、规则生成、策略框架 |
| `05_攻防对抗` | 攻防对抗 | 对抗手法、攻击案例、防御策略（预留） |
| `06_模型建设` | 模型建设 | 风控模型、特征、训练（预留） |
| `07_平台能力` | 平台能力 | 风控平台、引擎、工具（预留） |
| `08_监控运营` | 监控运营 | 监控、告警、运营 SOP（预留） |
| `09_合规治理` | 合规治理 | 合规、数据治理（预留） |
| `10_复盘案例` | 复盘案例 | 事件复盘、经验总结（预留） |

## 二、每篇 MD 的 frontmatter 字段规范

```yaml
---
title: <文档标题>
category: <必须是上表 10 类目名之一，如「风控总览」>
source_url: <飞书原文 URL>
source_token: <飞书 token>
source_type: wiki | docx | external
doc_type: 指标口径 | 业务介绍 | 标签定义 | 规则策略 | 其他
tags: [<受控词表内的标签>]
metrics: [<涉及的指标名，无则 []>]
business_lines: [<涉及业务线，无则 []>]
summary: <一句话摘要，≤50 字，用于 index.md 路由>
last_synced: <YYYY-MM-DD>
---
```

## 三、正文分节约定（frontmatter 之后）

固定顺序：`## 适用场景` → `## 核心概念` → `## 关键指标口径`（含指标才有，须逐条结构化）→ `## 规则 / 策略要点` → `## 原文正文`（保留完整原文，含表格/SQL，**不切块不截断**）。

## 四、tags 受控词表（新增文档只能从中选，扩词须先在此登记）

- 领域：`支付风控`、`交易风控`、`账号安全`
- 指标：`指标`、`口径`、`拦截率`、`资损率`、`净资损率`、`ATO`、`误杀率`、`成功率`
- 对象：`黑标`、`白标`、`黑白标签`、`False Positive`、`3DS`、`CheckPoint`、`账号体系`
- 业务线：`电商`、`直播`、`TikTokLive`、`LocalService`
- 动作：`规则优化`、`规则生成`、`策略`
- 产品：`PIPO`、`GPP`、`TTS`

## 五、business_lines 枚举
`电商`、`直播`（= TikTok Live）、`LocalService`、`全线`。

## 六、doc_type 枚举
`指标口径`、`业务介绍`、`标签定义`、`规则策略`、`其他`。

## 七、命名规范
文件名去空格/方括号/特殊字符；与 `三、目录结构`（DESIGN.md）及 `manifest.json` 的 `path` 保持一致，便于 `Read("<相对路径>")` 稳定引用。
